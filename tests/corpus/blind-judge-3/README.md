# Third Blind Benchmark (2026-11-16)

80 Rust repositories that no earlier corpus or benchmark used, chosen by a fixed rule before any tool ran on them ([repositories.txt](repositories.txt)): GitHub search `language:rust stars:500..5000 pushed:>2026-05-16 archived:false fork:false`, sorted by stars, the first 80 with a root `Cargo.lock` (315 repositories excluded as already seen), pinned to their default branch.

The first two blind runs used the crates with the most downloads: libraries with almost no unused dependencies (3 certain ones among 566 judged), which measured precision but not recall. These mid-size applications and workspaces have many more.

## Unused dependencies, judged by rustc

Run on GitHub Actions with the [blind benchmark workflow](../../../.github/workflows/blind-benchmark.yml) ([run 43841352501](https://github.com/HarpeLm/CargoScope/actions/runs/43841352501)): tools frozen at the start (CargoScope at commit `c441bcc`, cargo-machete 0.9.2, cargo-shear 1.14.1), then `cargo check --workspace --all-targets --all-features` with Rust 1.99.1 and rustc's `unused_crate_dependencies` lint on a disposable runner per repository. 31 repositories compiled and were judged (2,850 dependencies, 104 unused according to rustc); 49 did not compile with Rust 1.99.1 and all features (system libraries, newer minimum Rust versions, nightly features).

**Blind result, as frozen:**

| | Reported and judged | Correct | Wrong | Precision | rustc's unused found (of 104) |
|---|---|---|---|---|---|
| **CargoScope** (`likely-unused`) | 98 | 86 | 12 | **87.8%** | 82 (78.8%) |
| CargoScope with `--show-uncertain` | 143 | 121 | 22 | 84.6% | 104 (100%) |
| cargo-machete (default) | 123 | 101 | 22 | 82.1% | 87 (83.7%) |
| cargo-shear (default) | 123 | 115 | 8 | **93.5%** | 98 (94.2%) |

On this set, **cargo-shear did better than CargoScope** in both precision and recall. This is the result of the blind run, kept as it is.

**Why CargoScope was wrong (12):**

- **10 in two repositories: source files that are symbolic links.** `mini-lsm`'s binaries (`src/bin/mini-lsm-cli.rs -> ../../../mini-lsm-starter/...`) and actix examples' `websockets/echo/src/client.rs` are links; CargoScope never followed links, so `clap`, `nom`, `rand`, `rustyline`, `awc` and `tokio-stream` looked unused.
- **1: `=> ::imageflow_http_helpers::fetch_bytes(url)`** in a match arm, read as the continuation of a path (the `>` of `=>` taken for the end of `<T as X>`).
- **1: `linkme` in RedisJSON**, needed by a macro of another crate that expands to `linkme::...` in the caller. cargo-shear and cargo-machete make the same mistake; it cannot be seen without reading the dependencies' sources.

**Fixes, after the run (not blind):** links that resolve inside the workspace are now followed (links that leave it never are), `=> ::` and `-> ::` start a path, and a dependency mentioned in documentation is kept only for a code-like mention (`name::`, `` `name` ``, `[name]`, `use name`), no longer for prose ("which", "either") or file names (`Cargo.toml` for `toml`) — commit `d759f04`. Re-scored on the same rustc verdicts:

| | Correct | Wrong | Precision | rustc's unused found |
|---|---|---|---|---|
| CargoScope after the fixes | 90 | 1 (`linkme`) | 98.9% | 82 (78.8%) |
| cargo-shear (unchanged) | 115 | 8 | 93.5% | 98 (94.2%) |

The remaining recall gap is CargoScope's caution: the 22 dependencies rustc calls unused that CargoScope lists only as `possibly-unused` are kept for reasons rustc cannot see — code generated by a build script (6–8), a transitive dependency declared with `features` (8–10), an optional dependency forwarding a feature, a `-sys` crate linked for its native library, or a mention in doc examples, which `cargo test --doc` compiles but rustc's lint does not judge.

The same fixes, checked on the earlier benchmarks: the 73 libraries judged by rustc stay at 13 correct out of 13; the labelled corpus of 70 applications goes from 245 to **252 correct out of 254** (7 new findings, all checked by reading the code and labelled; the 2 wrong are the known egui cases).

### Narrowing the cautious rules (commit `631a663`, not blind)

The rules that keep a dependency as `possibly-unused` were then checked one by one against all three sets, and narrowed only where the data showed they protected nothing:

- **Generated code** now explains a dependency only if the build script can produce code for it: it names the crate (`"uuid::Uuid::new_v4()"` in a string counts), the crate is in the tree of its build-dependencies, or a generator `X-build`/`X-codegen` is one (`tonic-prost-build` writes `tonic_prost::`). A build script that reads other files keeps the old caution: yew's website tests are generated from Markdown pages and use crates `build.rs` never names.
- **Selecting features of a transitive dependency**: declaring only `derive`, or only `default-features = false`, no longer counts, since neither can change what other crates get. Features that do (`preserve_order`, `zlib-rs`, `wasm_js`…) still keep the dependency.

| | Third blind set: correct / wrong | rustc's unused found | 73 libraries | 70 applications (labelled) |
|---|---|---|---|---|
| Before | 90 / 1 | 82 of 104 (78.8%) | 13 / 0 | 252 correct of 254 |
| **After** | **93 / 1** | **85 of 104 (81.7%)** | 13 / 0 | **287 correct of 290** |
| cargo-shear | 115 / 8 | 98 of 104 (94.2%) | 16 / 2 | |

The 33 new findings in the labelled corpus were all checked by reading the code and labelled. The third wrong one there, `locked-tripwire` in atuin, is a crate kept only for a side effect: no static rule can tell it from an unused one, and it was kept before only because the package also had generated code (now marked as a known limitation, like egui's compile-check crate).

What CargoScope still leaves as `possibly-unused` is deliberate: features that change a crate for its other users, intra-doc links and facade crates, optional dependencies a feature names (which `cargoscope fix` cannot remove cleanly yet), platform-specific dependencies, and code generated by build scripts that read other files. cargo-shear reports those, so it finds more and errs more.

## Advisories, against cargo-audit 0.23.0

74 repositories fetched (`cargo fetch --locked`), both advisory databases downloaded the same day.

- **Before ignore lists, both tools report the same 1,376 advisories** (vulnerabilities and informational notices), none on one side only — after one fix: CargoScope read the `patched` ranges with Cargo's rule that a pre-release never matches, so fixed pre-releases (`blake2 0.11.0-rc.6`, `hickory-proto 0.26.0-beta.3`) were reported as vulnerable (5 false positives, commit `b219abb`).
- Each tool honours its own ignore file: cargo-audit `.cargo/audit.toml`, CargoScope `deny.toml`. CargoScope now also reads `.cargo/audit.toml` when there is no `cargoscope.toml`.
- **Yanked versions:** 67 found by both, **8 found only by CargoScope**, all checked as yanked in the crates.io index (`pest 2.6.0`, `chacha20 0.10.0`, `spin 0.9.8`…).

## Policy, against cargo-deny 0.20.2

The 16 repositories with their own `deny.toml`, with `cargo deny check licenses bans sources` and CargoScope reading the same file. Two differences led to fixes (commits `7114ed5`, `94ca0b4`):

- pgrx's `deny.toml` keeps its graph settings (`targets`, `all-features`) at the top level, an older layout cargo-deny still reads; CargoScope ignored them and checked a wasm32-only crate.
- dora's root package has only dev-dependencies; cargo-deny's graph without dev-dependencies starts from every workspace member it reaches, CargoScope's only from the root package, so no license was checked there.

After them: **the same errors (1 shared, 0 on either side only) and the same 14 `unused-allowed-license` warnings.** The 28 repositories of [deny-toml.md](../deny-toml.md) are unchanged (12 shared errors, 0 differences).

## Crates in several versions, against `cargo tree --duplicates`

`cargo tree --workspace --duplicates --target all --all-features -e normal,build,dev` on the 74 repositories: **2,441 crates reported by both**, 253 by CargoScope only, 4 by `cargo tree` only. The 253 are in `Cargo.lock` but built by no feature or platform of the workspace (CargoScope reads the lockfile without running Cargo, as documented). The 4 are a workspace member with the same name as a crates.io crate (`mysql` in actix examples), which is not a duplicate.

## Speed

Total time on the 74 repositories (macOS, M-series, warm caches):

| | Total | Median per repository | Checks |
|---|---|---|---|
| **CargoScope `scan`** | **107 s** | **0.57 s** | advisories, unused, licenses, versions, duplicates, weights, policy, maintenance |
| cargo-audit | 35 s | 0.43 s | advisories |
| cargo-deny `check advisories` | 110 s | 1.35 s | advisories |
| cargo-machete | 32 s | 0.21 s | unused |
| cargo-shear | 35 s | 0.39 s | unused |

One CargoScope scan costs about half of running cargo-audit, cargo-deny, cargo-machete and cargo-shear (212 s).

`cargoscope update` (downloads, once before scanning) took a median 65 s per repository, mostly the maintenance data: two crates.io requests per direct dependency at one per second. The repository URL now comes from the local sources (commit `d5ffbcd`): 250 s become 191 s on maplibre/martin (145 direct dependencies). The owners request stays, so projects with more than 30 direct dependencies are told how long the first refresh takes; the data is kept for a week.
