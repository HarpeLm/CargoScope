# Unused-Dependency Corpus

[`corpus.toml`](corpus.toml) pins 70 open-source Rust repositories to a commit and labels, by reading their code, the dependencies CargoScope reports as `likely-unused`:

- `unused`: the dependency is really unused by the package's code.
- `used`: CargoScope reported it wrongly at some point. These labels guard against regressions.

Replay it with:

```sh
cargo run -p cargoscope-corpus -- target/corpus
```

The tool fetches each repository with `git`, creates a `Cargo.lock` with `cargo generate-lockfile` when the repository has none (this only resolves versions; no build script or project code runs), scans it, and compares the findings with the labels. It fails on any wrong or unlabelled finding, or below 97% precision.

## Results (2026-11-12)

Precision is measured on `likely-unused` findings only, the ones shown by default.


| Set | Repositories | `likely-unused` reported | Correct | Precision |
|---|---|---|---|---|
| Development | 30 | 11 | 11 | 100% |
| Held-out, first run | 10 | 11 | 10 | **90.9%** |
| Held-out, after the fix below | 10 | 9 | 9 | 100% |
| **Held-out 2** (bevy, nushell, polars, deno, cargo, helix...) | 15 | 110 | 103 | **93.6%** |
| Held-out 2, after the fixes below | 15 | 101 | 101 | 100% |
| **Held-out 3** (tokio, rustls, wgpu, iced, egui, typst, zola, yew...) | 15 | 52 | 47 | **90.4%** |
| Held-out 3, after fixing the typst regression | 15 | 49 | 47 | 95.9% |

**How to read these numbers:**

- The development set was used to design the rules. Its first run reported 60 `likely-unused` dependencies, most of them wrong. Each wrong one led to a rule: following `mod` declarations from targets outside `src/`, build scripts that include files, derive helper attributes, paths in attribute strings, macros of sibling crates, library names that differ from package names, generated code, documentation links, and feature forwarding. Its 100% therefore says little about unseen projects.
- The held-out set was labelled before any change. Its only wrong finding (`phf` in typos, used in a skipped 2 MiB generated file) revealed a bug: skipped files did not lower confidence. After the fix, the held-out set is no longer independent. **90.9% on unseen code is the honest figure**, below the 97% target of SPEC.md; a new held-out set is needed before claiming the target.
- Held-out 2 was labelled before any change, on large workspaces. Its 7 wrong findings have two causes: dependencies whose paths are generated by derive macros of another crate (6 times `bevy_extract`, used through `#[derive(ExtractResource)]`), which static analysis cannot see without expanding the macro; and a `#[path]` module declared inside a function of a build script (nushell). Both causes were then fixed: `#[path]` modules inside functions are followed, and crates that workspace proc-macro crates generate paths to (in `quote!` bodies or as crate-name strings such as `get_path("bevy_extract")`, path dependencies included) lower a finding to `possibly-unused`. Held-out 2 is therefore no longer independent: **93.6% remains the best estimate on unseen code**, below the 97% target, until a third held-out set is measured.
- Held-out 3 was labelled before any change. Its 5 wrong findings: 3 in typst-cli, whose build script declares `#[path = "src/args.rs"] #[expect(dead_code)] mod args;` (a second attribute between `#[path]` and `mod`, which the rule added after held-out 2 does not accept, a regression); and 2 in egui's `tests/test_egui_extras_compilation`, an intentionally empty crate that only checks that its dependencies compile together. Counting those 2 as correct would give 94.2%. The typst regression was then fixed (`#[path]` is now found among several attributes); the 2 intentional egui dependencies remain. **Over the three held-out sets, precision on unseen code was 90.9%, 93.6% and 90.4%: about 91–94%, below the 97% target.**
- Their "correct" labels mean that the dependency name appears nowhere in the package (code, strings, docs) and no known macro generates it; they were not checked with the compiler.
- Recall is lower by design: on the development set, 9 of 20 dependencies labelled `unused` are only reported as `possibly-unused`, for example `tokio-test` next to tokio, or `heck` in a package with a skipped file.
- Labels come from reading code, not from the compiler. Repositories without a committed `Cargo.lock` get one generated at run time, so their results can drift slightly over time.
