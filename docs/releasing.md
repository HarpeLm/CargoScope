# Releasing CargoScope

A release is started by pushing a version tag. Everything else runs in GitHub Actions.

| Channel | Workflow | Needs |
|---|---|---|
| GitHub Releases: binaries for macOS, Linux and Windows, SHA256, attestations, shell and PowerShell installers | `release.yml` (generated by [dist](https://github.com/axodotdev/cargo-dist)) | Nothing |
| crates.io (`cargo install cargoscope`) | `publish-crates.yml`, called by `release.yml` | `CARGO_REGISTRY_TOKEN` secret |
| Homebrew (`brew install HarpeLm/tap/cargoscope`) | `release.yml` | `HarpeLm/homebrew-tap` repository and `HOMEBREW_TAP_TOKEN` secret |
| npm (`npx cargoscope`) | `release.yml` | `NPM_TOKEN` secret |
| PyPI (`pip install cargoscope`, `uvx cargoscope`) | `pypi.yml` | PyPI trusted publisher (no token) |
| GitHub Action (`uses: HarpeLm/CargoScope@v0.1.0`) | `action.yml` at the repository root | The GitHub Release |

## One-time setup (maintainer)

1. **crates.io**: create an API token with the `publish-new` and `publish-update` scopes, then add it as the repository secret `CARGO_REGISTRY_TOKEN`.
2. **Homebrew**: create the public repository `HarpeLm/homebrew-tap` (empty is fine). Create a fine-grained GitHub token with "Contents: read and write" on that repository only, and add it as `HOMEBREW_TAP_TOKEN`.
3. **npm**: create an automation access token on npmjs.com and add it as `NPM_TOKEN`.
4. **PyPI**: on pypi.org, add a "pending publisher" for project `cargoscope`: owner `HarpeLm`, repository `CargoScope`, workflow `pypi.yml`, environment `pypi`. Then create the `pypi` environment in the repository settings.

Secrets are added in the repository settings, under Secrets and variables, Actions.

## Each release

1. Set `version` in `[workspace.package]` of `Cargo.toml` and in the path dependencies of the crates (the code between releases says `0.1.0-dev`), then run `cargo build` so `Cargo.lock` follows.
2. Run `dist plan` to check what will be built.
3. Commit, then tag and push: `git tag v0.1.0 && git push origin v0.1.0`.

Pre-releases (`v0.1.0-alpha.1`) build GitHub Releases, installers and the npm package, but are not published to crates.io, and `pypi.yml` only reacts to stable tags.

## Notes

- `release.yml` is generated by `dist generate`, then patched by hand on one line (the custom crates.io job, see `allow-dirty` in `dist-workspace.toml`). Re-apply that patch after regenerating.
- `cargo package --workspace --exclude cargoscope-corpus` checks that the crates build from their packaged sources before a release.

After a release, set the version back to the next `-dev` version, so that a build from `main` never claims to be a published release.
